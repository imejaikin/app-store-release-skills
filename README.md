# App Store Release Skills

Практические инструкции и навыки для ИИ-агента: подготовка приложения к App Store и настройка Apple In-App Purchases. Подходят для Swift, Flutter, React Native и других стеков с iOS-сборкой.

Здесь нет данных конкретной компании, приложений, серверов или учётных записей. Пакет содержит инструкции, а не готовый сервис загрузки и не доступ к аккаунту Apple. Доступные инструменты агент определяет в своём окружении.

## Что внутри

| Навык | Задачи | Руководство для человека |
|---|---|---|
| `app-store-release` | Доступы, подпись, архив, карточка, TestFlight, подача на модерацию и выпуск | [Порядок выпуска](skills/app-store-release/references/release-guide.md) |
| `apple-in-app-purchases` | Товары и подписки, StoreKit, серверная проверка, Sandbox, восстановление | [Покупки и проверка](skills/apple-in-app-purchases/references/payments-guide.md) |

[Роли и действия владельца](skills/app-store-release/references/roles.md) объясняют, почему App Manager достаточно для обычной публикации, но недостаточно для некоторых деклараций.

## Установка

Склонируйте репозиторий:

```sh
git clone https://github.com/imejaikin/app-store-release-skills.git
cd app-store-release-skills
```

Для Codex скопируйте обе папки из `skills/` в пользовательский каталог навыков `~/.codex/skills/`. Для Claude Code — в `~/.claude/skills/`. Перед копированием проверьте, что не перезаписываете существующий навык. Для другого агента используйте поддерживаемый им каталог `SKILL.md`; сами руководства можно читать отдельно.

Запрос агенту:

```text
Используй $app-store-release. Подготовь приложение из текущего репозитория
к отправке в App Store. Проверь существующую карточку и продолжи с неё.
```

Для покупок:

```text
Используй $apple-in-app-purchases. Проверь StoreKit и серверную выдачу
доступа, настрой товары и составь фактический статус проверки.
```

Уточните желаемый результат: только подготовка, TestFlight, отправка на модерацию или публикация. Это разные действия. Правила и разрешения вашего окружения сохраняют силу.

## Что пакет помогает не перепутать

- Роль в App Store Connect, доступ к Certificates, Identifiers & Profiles и вход в Xcode — разные уровни доступа.
- Admin не заменяет Account Holder при подписании договоров Apple и открывает доступ ко всем приложениям организации.
- Загрузка архива, обработанный билд, подача на проверку, одобрение и публичный релиз — разные состояния.
- Физическое устройство полезно для проверки платежей, но отсутствие устройства само по себе не является отдельным запретом подачи App Review. Невыполненные проверки остаются явно невыполненными.
- Настоящая ошибка в основном сценарии и ещё не выполненный тест требуют разных решений.
- Ошибка создания карточки иногда оставляет созданный объект: сначала перечитать, затем повторять.
- Реальные ключи и пароли не входят в инструкции, git, скриншоты или отчёт.

Документация Apple проверена 26.10.2026. Перед конкретным релизом сверяйте изменяемые требования по ссылкам в руководствах. Формат навыков проверен валидатором, инструкции — независимым разбором сценариев; это не доказательство прохождения App Review для любого приложения.
